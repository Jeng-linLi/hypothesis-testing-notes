Q1●○○ 基礎寫 H₀ / Ha
題目　某飲料標示「平均含糖量不超過 8 g」。消費者團體懷疑實際上超標，決定抽樣檢驗。設 μ 為該飲料真實平均含糖量。寫出 H₀ 與 Ha，並說明是單尾還是雙尾、哪一尾。
Question. A drink is labelled "mean sugar content at most 8 g". A consumer group suspects it is actually higher and samples the product. Let μ be the true mean sugar content. State H₀ and Ha, and say whether the test is one- or two-tailed (which tail).
顯示詳解 / Show solution
  1. 認出「想證明什麼」/ What do we want to prove?
    「懷疑超標」＝想證明 μ > 8。想證明的話放 Ha，不能放 H₀。
    "Suspect it is higher" means we want to establish μ > 8. What we want to prove goes in Ha, never in H₀.
  2. H₀ 是現況 / H₀ is the status quo
    標示的說法「μ ≤ 8」是現況，放 H₀。練習時通常寫成邊界形式 H₀: μ = 8，因為臨界值要在等號成立的邊界上算。
    The label's claim μ ≤ 8 is the status quo, so it goes in H₀. In practice we write the boundary form H₀: μ = 8, because the critical value is computed at that boundary.
  3. 判斷尾巴 / Determine the tail
    Ha 用「>」→ 只有右邊極端才構成證據 → 右尾（upper / right-tailed）。
    Ha uses ">" → only a large value counts as evidence → upper (right) tail.
  4. 常見錯 / Common mistake
    寫成 Ha: μ ≥ 8 是錯的：Ha 不能含等號。寫成 H₀: μ ≠ 8 也錯：那就變成雙尾了。
    Ha: μ ≥ 8 is wrong: Ha never contains equality. H₀: μ ≠ 8 is also wrong: that would make it two-tailed.
答案：H₀: μ ≤ 8（運算時用 μ = 8）vs Ha: μ > 8，右尾檢定。Answer: H₀: μ ≤ 8 (use μ = 8 for computation) vs Ha: μ > 8, an upper-tailed test.
Q2●○○ 基礎單尾／雙尾
題目　填充機器出廠設定為每瓶 500 ml。品管部門懷疑設定值偏離了 500（可能偏多，也可能偏少），想做檢定。寫出 H₀、Ha 並指出尾巴型態。若改為「懷疑填充不足」，答案怎麼變？
Question. A filling machine is set to 500 ml per bottle. Quality control suspects the setting has drifted away from 500—it could be higher or lower. State H₀, Ha and the tail type. How would your answer change if the suspicion were "the fill is too low"?
顯示詳解 / Show solution
  1. 關鍵字：「偏離」/ Keyword: "drifted"
    「偏離」沒有方向，代表兩個方向都算證據 → Ha 用 μ ≠ 500 → 雙尾。
    "Drifted" has no direction: either extreme counts as evidence → Ha uses μ ≠ 500 → two-tailed.
  2. 雙尾的拒絕域 / Two-tailed rejection region
    α 要拆成兩半，各 α/2 放在兩邊。α = .05 時臨界值是 ±1.960（σ 已知）。
    α is split into α/2 on each side. At α = .05 the critical values are ±1.960 (σ known).
  3. 改問「不足」/ If the suspicion is "too low"
    有方向了：Ha: μ < 500，左尾。此時 α 全放左邊，臨界值 −1.645（α = .05、σ 已知）。
    Now there is a direction: Ha: μ < 500, a lower tail. All of α goes to the left; the critical value is −1.645 (α = .05, σ known).
  4. 為什麼不能隨便選雙尾 / Why not always use two tails
    雙尾比較保守：同樣 α 下，要更極端的資料才會拒絕（因為臨界值 1.960 > 1.645）。但如果有清楚的事前方向假設，用單尾能得到比較大的 power。方向必須在看到資料前就決定。
    Two-tailed is conservative: at the same α you need a more extreme result (1.960 > 1.645). With a genuine pre-specified direction, a one-tailed test has more power. The direction must be decided before seeing the data.
答案：偏離 → H₀: μ = 500 vs Ha: μ ≠ 500，雙尾；不足 → Ha: μ < 500，左尾。Answer: Drift → H₀: μ = 500 vs Ha: μ ≠ 500, two-tailed; too low → Ha: μ < 500, lower-tailed.
Q3●○○ 基礎型一／型二錯誤
題目　公司考慮上架一套新客服系統。檢定設為 H₀: 新系統平均處理時間沒有比舊系統短，Ha: 有變短。請用大白話說明：(a) 型一錯誤是什麼、代價是什麼？(b) 型二錯誤是什麼、代價是什麼？(c) 若老闆說「我寧可慢一點上線，也不要換了結果沒用」，該調大還是調小 α？
Question. A firm is considering a new customer-service system. The test is H₀: the new system is not faster vs Ha: it is faster. In plain language: (a) What is a Type I error and what does it cost? (b) What is a Type II error and what does it cost? (c) If the boss says "I would rather launch late than launch something useless", should α increase or decrease?
顯示詳解 / Show solution
  1. 型一 = 員警抓錯人 / Type I = false alarm
    H₀ 其實為真（新系統根本沒比較快），卻拒絕 H₀、宣布有效 → 白白換系統，浪費採購與訓練成本。機率 = α。
    H₀ is actually true (no real speed-up), but we reject it and declare success → we switch systems for nothing, wasting purchase and training costs. Probability = α.
  2. 型二 = 放走犯人 / Type II = missed signal
    Ha 其實為真（新系統真的比較快），卻沒拒絕 H₀ → 錯過一個真正有效的改善。機率 = β。
    Ha is actually true (it really is faster), but we fail to reject H₀ → we miss a real improvement. Probability = β.
  3. 老闆的話翻成統計語言 / Translate the boss
    「不要換了結果沒用」＝怕型一錯誤 → 要壓低 α（例如 .05 → .01）。代價是 β 上升、power 下降，也就是需要更多樣本才抓得到效果。
    "Don't launch something useless" = fear of Type I error → lower α (e.g. .05 → .01). The price: β rises, power falls, so you need a larger sample to detect the same effect.
  4. 記憶法 / Memory hook
    α = P(拒絕 H₀ | H₀ 為真)；β = P(不拒絕 H₀ | Ha 為真)；power = 1 − β 是「有效就抓得到」的能力。
    α = P(reject H₀ | H₀ true); β = P(fail to reject H₀ | Ha true); power = 1 − β is the ability to detect a real effect.
答案：(a) 沒效卻上線，代價是成本，機率 α；(b) 有效卻沒上線，代價是錯失改善，機率 β；(c) 調小 α（代價是 power 下降）。Answer: (a) Launching an ineffective system, cost = wasted money, probability α; (b) missing an effective one, cost = lost improvement, probability β; (c) decrease α (at the cost of power).
Q4●○○ 基礎信賴區間 ↔ 檢定
題目　某母體平均值 μ 的 95% 信賴區間算出來是 [98.2, 104.6]。不重新算資料，直接回答：在 α = .05 的雙尾檢定下，(a) 檢定 H₀: μ = 100 會拒絕嗎？(b) 檢定 H₀: μ = 105 呢？(c) 為什麼可以這樣判斷？
Question. A 95% confidence interval for μ is [98.2, 104.6]. Without recomputing anything, answer: at α = .05 in a two-tailed test, (a) would you reject H₀: μ = 100? (b) What about H₀: μ = 105? (c) Why does this work?
顯示詳解 / Show solution
  1. 把區間想成「不被拒絕的值」/ An CI is a set of non-rejected values
    95% CI 恰好等於：所有在 α = .05 雙尾檢定中不會被拒絕的 μ₀ 所構成的集合。所以只要看 μ₀ 是否落在區間裡。
    A 95% CI is exactly the set of μ₀ values that would not be rejected by an α = .05 two-tailed test. Just check whether μ₀ lies inside.
  2. 逐項判斷 / Apply it
    100 ∈ [98.2, 104.6] → 不拒絕；105 ∉ [98.2, 104.6] → 拒絕。
    100 ∈ [98.2, 104.6] → do not reject; 105 ∉ [98.2, 104.6] → reject.
  3. 方向要對上 / The correspondence needs matching tails
    這個等價關係只對雙尾檢定成立，且信賴水準要剛好是 1 − α（95% ↔ .05）。若是單尾檢定，要用 90% 單側界限來對照。
    This equivalence holds for two-tailed tests with confidence level 1 − α (95% ↔ .05). For a one-tailed test you would need a 90% one-sided bound instead.
答案：(a) 不拒絕；(b) 拒絕；(c) 95% CI 就是在 α = .05 雙尾檢定下所有不被拒絕的 μ₀ 的集合。Answer: (a) Do not reject; (b) reject; (c) a 95% CI is the collection of all μ₀ not rejected at α = .05 (two-sided).
Q5●●○ 中階Z 檢定 · 右尾
題目　已知某製程的母體標準差 σ = 10。過去的平均值為 μ₀ = 50。抽 n = 25 件，得到 x̄ = 53.5。在 α = .05 下，是否有證據支持平均值已上升？請完整寫出檢定過程（含 p 值）。
Question. A process has known population standard deviation σ = 10 and historical mean μ₀ = 50. A sample of n = 25 gives x̄ = 53.5. At α = .05, is there evidence that the mean has increased? Show the full test, including the p-value.
顯示詳解 / Show solution
  1. 假設 / Hypotheses
    H₀: μ = 50 vs Ha: μ > 50，「上升」→ 右尾。
    H₀: μ = 50 vs Ha: μ > 50; "increased" → upper tail.
  2. 選檢定與標準誤 / Test and standard error
    σ 已知 → 用 Z 檢定。SE = σ/√n = 10/√25 = 10/5 = 2。
    σ known → Z test. SE = σ/√n = 10/√25 = 10/5 = 2.
  3. 算統計量 / Test statistic
    z = x̄ − μ₀σ/√n = 53.5 − 502 = 1.75
  4. 判準一：臨界值 / Criterion 1: critical value
    右尾 α = .05 → z₀.₀₅ = 1.645。因為 1.75 > 1.645，落入拒絕域。
    Upper tail α = .05 → z₀.₀₅ = 1.645. Since 1.75 > 1.645, it falls in the rejection region.
  5. 判準二：p 值 / Criterion 2: p-value
    p = P(Z > 1.75) = 1 − Φ(1.75) = 0.0401。0.0401 < 0.05，同樣拒絕。兩種方法永遠一致。
    p = P(Z > 1.75) = 1 − Φ(1.75) = 0.0401. Since 0.0401 < 0.05, reject as well. The two methods always agree.
  6. 結論要回到情境 / Conclude in context
    在 5% 顯著水準下，樣本資料提供足夠證據支持平均值已上升。注意話術：是「有證據支持 Ha」，不是「證明 Ha 為真」。
    At the 5% level the data provide sufficient evidence that the mean has increased. Mind the wording: "evidence supports Ha", not "Ha is proven".
答案：z = 1.75 > 1.645，p = 0.0401 < .05 → 拒絕 H₀，有證據支持平均值上升。Answer: z = 1.75 > 1.645, p = 0.0401 < .05 → reject H₀; evidence supports an increased mean.
Q6●●○ 中階Z 檢定 · 雙尾
題目　某產品標準重量為 μ₀ = 100 g，製程標準差已知為 σ = 15 g。抽 n = 36 件，測得 x̄ = 106 g。在 α = .05 下，製程平均值是否偏離標準值？
Question. The target weight is μ₀ = 100 g with known process standard deviation σ = 15 g. A sample of n = 36 has x̄ = 106 g. At α = .05, has the process mean drifted from the target?
顯示詳解 / Show solution
  1. 假設 / Hypotheses
    「偏離」無方向 → H₀: μ = 100 vs Ha: μ ≠ 100，雙尾。
    "Drifted" has no direction → H₀: μ = 100 vs Ha: μ ≠ 100, two-tailed.
  2. 標準誤與統計量 / SE and statistic
    SE = 15/√36 = 2.5；z = (106 − 100)/2.5 = 2.40。
    SE = 15/√36 = 2.5; z = (106 − 100)/2.5 = 2.40.
  3. 臨界值 / Critical values
    α 拆兩半：z₀.₀₂₅ = 1.960，拒絕域是 |z| > 1.960。2.40 > 1.960 → 拒絕。
    Split α: z₀.₀₂₅ = 1.960; reject when |z| > 1.960. Since 2.40 > 1.960, reject.
  4. p 值（雙尾要乘 2）/ p-value (double it)
    p = 2 × P(Z > 2.40) = 2 × 0.008198 = 0.0164。0.0164 < .05 → 拒絕。很多人忘了乘 2，得不到 0.0082 就以為更顯著——方向錯了但結論碰巧一樣，這類錯最危險。
    p = 2 × P(Z > 2.40) = 2 × 0.008198 = 0.0164. Since 0.0164 < .05, reject. Forgetting the factor 2 gives 0.0082—same conclusion here, which is exactly why this mistake is dangerous.
  5. 結論 / Conclusion
    在 5% 水準下，製程平均值與 100 g 有顯著差異；資料指向「偏重」。
    At the 5% level the mean differs significantly from 100 g; the data point to an overfill.
答案：z = 2.40，臨界值 ±1.960，p = 0.0164 → 拒絕 H₀。Answer: z = 2.40, critical ±1.960, p = 0.0164 → reject H₀.
Q7●●○ 中階α 的影響
題目　某零件的規格平均值為 120，已知 σ = 20。抽 n = 64，得到 x̄ = 115。有人主張「平均值低於規格」。請分別在 α = .05 與 α = .01 下檢定，並說明為什麼兩個結論不同。
Question. A part has specification mean 120 with known σ = 20. A sample of n = 64 gives x̄ = 115. Someone claims the mean is below specification. Test at α = .05 and at α = .01, and explain why the conclusions differ.
顯示詳解 / Show solution
  1. 假設 / Hypotheses
    H₀: μ = 120 vs Ha: μ < 120，左尾。
    H₀: μ = 120 vs Ha: μ < 120, lower tail.
  2. 統計量 / Statistic
    SE = 20/√64 = 2.5；z = (115 − 120)/2.5 = −2.00。注意：計算法則用絕對值比大小，符號只決定看哪一尾。
    SE = 20/√64 = 2.5; z = (115 − 120)/2.5 = −2.00. Compare magnitudes; the sign only tells you which tail.
  3. p 值 / p-value
    p = Φ(−2.00) = 0.0228。這個值不隨 α 改變。
    p = Φ(−2.00) = 0.0228. This value does not change with α.
  4. 兩種判決 / Two decisions
    α = .05：臨界值 −1.645，−2.00 < −1.645 → 拒絕（也可用 p = .0228 < .05）。
    α = .01：臨界值 −2.326，−2.00 > −2.326 → 不拒絕（p = .0228 > .01）。
    α = .05: critical −1.645, −2.00 < −1.645 → reject (also p = .0228 < .05).
    α = .01: critical −2.326, −2.00 > −2.326 → do not reject (p = .0228 > .01).
  5. 這題在考什麼 / The point
    「p = .0228 很小」不等於任何門檻都過。α 是事前訂的容錯水準；不能看到 p = .0228 之後才改選 α = .05。這也是「p-hacking」的最基本型態。
    "p = .0228 is small" does not clear every threshold. α is a pre-set tolerance; you cannot switch to α = .05 after seeing p = .0228. That is the most basic form of p-hacking.
答案：z = −2.00，p = 0.0228；α = .05 拒絕，α = .01 不拒絕。門檻必須事先定。Answer: z = −2.00, p = 0.0228; reject at α = .05, do not reject at α = .01. Fix the threshold in advance.
Q8●●○ 中階臨界值翻譯
題目　延續 Q5：μ₀ = 50、σ = 10、n = 25、α = .05 右尾。(a) 把 z 尺度上的臨界值換算成 x̄ 尺度上的臨界值 c。(b) 若觀測到的 x̄ 是 53.2（不是 53.5），請用 c 直接判決。(c) 為什麼不能只拿 x̄ 跟 μ₀ = 50 比？
Question. Continue Q5: μ₀ = 50, σ = 10, n = 25, upper tail at α = .05. (a) Convert the z-scale critical value to a critical value c on the x̄ scale. (b) If the observed x̄ were 53.2 (not 53.5), decide using c. (c) Why can't you just compare x̄ with μ₀ = 50?
顯示詳解 / Show solution
  1. 把 α 翻譯過去 / Translate α to the data scale
    c = μ₀ + zα · σ√n = 50 + 1.644854 × 2 = 53.2897
    意思是：只要 x̄ > 53.29 就拒絕。決策規則從「z > 1.645」變成「x̄ > 53.29」，兩者完全等價。
    Interpretation: reject whenever x̄ > 53.29. The rule "z > 1.645" becomes "x̄ > 53.29"—exactly equivalent.
  2. 用 c 判決 / Apply c
    x̄ = 53.2 < 53.29 → 不拒絕。檢查：z = (53.2−50)/2 = 1.60 < 1.645，一致。
    x̄ = 53.2 < 53.29 → do not reject. Check: z = (53.2−50)/2 = 1.60 < 1.645; consistent.
  3. 直覺陷阱 / The intuition trap
    53.2 明明「比 50 大」，為什麼不算證據？因為抽樣本身就會波動：即使 μ 真的是 50，n = 25 的樣本平均也有 5% 的機會超過 53.29。門檻要算上抽樣誤差，不是加上「一點點」就好。
    53.2 is bigger than 50—why isn't that evidence? Because sampling varies: even if μ really is 50, a sample of 25 has a 5% chance of exceeding 53.29. The threshold must account for sampling error, not just add "a little".
  4. 對應到型一錯誤 / Link to Type I error
    這個 c 的定義就是：P(x̄ > c | μ = 50) = 0.05。所以誤報率剛好是 α。
    The definition of c is P(x̄ > c | μ = 50) = 0.05, so the false-alarm rate is exactly α.
答案：(a) c = 53.2897；(b) 53.2 < c，不拒絕；(c) 抽樣平均本身有變異，必須跟含抽樣誤差的 c 比，不是跟 μ₀ 比。Answer: (a) c = 53.2897; (b) 53.2 < c, do not reject; (c) x̄ varies by sampling, so compare it with c, which includes sampling error—not with μ₀.
Q9●●○ 中階t 檢定
題目　σ 未知。n = 16、x̄ = 22.4、s = 3.2，檢定 H₀: μ = 20 vs Ha: μ > 20，α = .05。(a) 算 t 統計量並判決。(b) 若有人誤用 Z 檢定，p 值會變成多少？差在哪裡？
Question. σ is unknown: n = 16, x̄ = 22.4, s = 3.2. Test H₀: μ = 20 vs Ha: μ > 20 at α = .05. (a) Compute t and decide. (b) If someone wrongly used a Z test, what p-value would they get, and what is the difference?
顯示詳解 / Show solution
  1. 選 t 不看 n，看 σ / Choose t by σ, not by n
    σ 未知、用 s 估計 → t 檢定，自由度 df = n − 1 = 15。「n > 30 就用 Z」是常見但錯誤的口訣；n 大只是讓 t 逼近 Z。
    σ unknown and estimated by s → t test with df = n − 1 = 15. "Use Z if n > 30" is a common but wrong rule of thumb; large n only makes t approach Z.
  2. 統計量 / Statistic
    t = x̄ − μ₀s/√n = 22.4 − 203.2/4 = 2.40.8 = 3.00

    p̂₁ = 36/200 = 0.18，p̂₂ = 30/250 = 0.12，差距 0.06（6 個百分點）。

  2. 檢定要 pool / Pool for the test
    在 H₀: p₁ = p₂ 為真的前提下，兩組資料可以合併估計共同比例：
    p̂_pool = (x₁+x₂)/(n₁+n₂) = 66/450 = 0.14667
    SE_pool = √(0.14667 × 0.85333 × (1/200 + 1/250)) = 0.03356

    p̂_pool = (x₁+x₂)/(n₁+n₂) = 66/450 = 0.14667

    |1.788| < 1.960，p = 2 × P(Z > 1.788) = 0.0738 > .05 → 不拒絕。看起來差 6 個百分點，但以這個樣本量還不到統計顯著。
    |1.788| < 1.960, p = 2 × P(Z > 1.788) = 0.0738 > .05 → do not reject. A 6-point gap looks large, but with this sample size it is not statistically significant.
  4. CI 不 pool / Do not pool for the CI
    信賴區間不限定 p₁ = p₂，所以要各自估計：

  5. 為什麼一個 pool 一個不 pool / Why the asymmetry
    檢定的前提就是 H₀ 成立（p₁ = p₂），所以可以合理使用共同比例；CI 的目的是估計「兩者到底差多少」，不能先假設它們相等。口訣：檢定 pool，區間不 pool。

Q19●●●● 綜合A/B 測試全流程
題目　某網站目前轉換率 p₁ = 0.12。產品經理希望偵測提升到 0.14 的效果，採用雙尾 α = .05、power .80。(a) 每組需要多少使用者？(b) 實驗後 A 組 4438 人中 560 人轉換、B 組 4438 人中 637 人轉換，請做出判決。(c) 若團隊每天偷看結果，看到顯著就停，有什麼問題？
Question. A website's current conversion rate is p₁ = 0.12. The PM wants to detect an increase to 0.14, using a two-tailed test at α = .05 with power .80. (a) How many users per group? (b) After the experiment, group A has 560 conversions in 4438 users and group B has 637 in 4438—make the decision. (c) What goes wrong if the team peeks daily and stops as soon as it is significant?
顯示詳解 / Show solution
  1. (a) 比例檢定的樣本數公式 / Sample size formula for two proportions
    n = [zα/2√(2p̄(1−p̄)) + zβ√(p₁(1−p₁)+p₂(1−p₂))]²(p₂−p₁)²
    p̄ = (0.12+0.14)/2 = 0.13；z₀.₀₂₅ = 1.9600；power .80 → β = .20，z₀.₂₀ = 0.8416。
    第一項 = 1.9600 × √(2×0.13×0.87) = 0.9322；第二項 = 0.8416 × √(0.1056+0.1204) = 0.4001。
    n = (0.9322+0.4001)² / 0.02² = 4437.36 → 4438 人/組（向上取整）。
    p̄ = (0.12+0.14)/2 = 0.13; z₀.₀₂₅ = 1.9600; power .80 → β = .20, z₀.₂₀ = 0.8416.
    Term 1 = 1.9600 × √(2×0.13×0.87) = 0.9322; term 2 = 0.8416 × √(0.1056+0.1204) = 0.4001.
    n = (0.9322+0.4001)² / 0.02² = 4437.36 → 4438 per group (round up).
  2. (b) 觀察結果 / Observed results
    p̂_A = 560/4438 = 0.1262（12.62%）；p̂_B = 637/4438 = 0.1435（14.35%）；差距 0.0174（1.74 個百分點）。
    注意：差距小於當初設計的 2 個百分點，但這很正常——設計用的 δ 是「值得偵測的最小效果」，不是「預期觀察到的效果」。
    p̂_A = 560/4438 = 0.1262 (12.62%); p̂_B = 637/4438 = 0.1435 (14.35%); gap 0.0174 (1.74 points).
    Note: the gap is smaller than the 2 points used in design. That is normal—δ is the smallest effect worth detecting, not the effect you expect to observe.
  3. (b) 檢定 / The test
    p̂_pool = (560+637)/(2×4438) = 0.13486
    SE = √(0.13486 × 0.86514 × 2/4438) = 0.007251
    z = 0.01735 / 0.007251 = 2.393；p = 2 × P(Z > 2.393) = 0.0167 < .05 → 拒絕 H₀，新版顯著較好。
    p̂_pool = (560+637)/(2×4438) = 0.13486
    SE = √(0.13486 × 0.86514 × 2/4438) = 0.007251
    z = 0.01735 / 0.007251 = 2.393; p = 2 × P(Z > 2.393) = 0.0167 < .05 → reject H₀; the new version is significantly better.
  4. (c) Peeking 問題 / The peeking problem
    每天都檢定一次等於做很多次檢定，而每次都有 α = 5% 的誤報機會。若偷看 14 天，至少一次假陽性的機率是 1 − 0.95¹⁴ ≈ 0.51——超過一半。而且「一顯著就停」會系統性地挑到高估效果的那一刻。
    解法：事先算好樣本數（本題 4438）、事先定 α，中途不看；若必須中途看，要用序貫檢定（sequential testing）或 alpha spending 方法調整門檻。
    Testing every day means many tests, each with a 5% false-alarm chance. Over 14 days the chance of at least one false positive is 1 − 0.95¹⁴ ≈ 0.51—more than half. Stopping at the first significant result also systematically picks an inflated effect.
    Fix: pre-compute the sample size (4438 here), fix α, and do not look early. If you must monitor, use sequential testing or alpha-spending boundaries.
  5. 統計顯著 ≠ 商業重要 / Significant ≠ important
    1.74 個百分點是否值得上線，要看每轉換的價值、改版成本與維護成本。p 值只回答「效果是不是 0」，不回答「效果夠不夠大」。
    Whether 1.74 points justifies a launch depends on value per conversion and engineering cost. A p-value answers "is the effect zero?", not "is it big enough?".
答案：(a) 每組 4438 人；(b) z = 2.393，p = 0.0167 → 拒絕 H₀；(c) 每天偷看 14 天，假陽性率升到約 51%，應事先定樣本數與停止規則。Answer: (a) 4438 per group; (b) z = 2.393, p = 0.0167 → reject H₀; (c) 14 daily peeks raise false-positive risk to about 51%—fix sample size and stopping rule in advance.
Q20●●●● 綜合錯誤診斷
題目　以下是某位助理寫的分析報告。請找出至少四個錯誤，逐條說明錯在哪、並給出更正。

「為檢驗新教法是否提高平均分，我們設 H₀: x̄ = 70，Ha: x̄ > 70。抽 30 名學生，得到 x̄ = 74.2、s = 8.5，算得 t = 2.71、p = 0.0056。因此在 α = .05 下拒絕 H₀，代表新教法有 99.44% 的機率有效。95% 信賴區間為 74.2 ± 1.96 × 8.5 = [57.54, 90.86]。若明天再抽 30 人重算，只要又顯著，就更能證明效果。」
Question. Below is an analysis report written by an assistant. Find at least four errors; for each, explain what is wrong and give the correction.

"To test whether a new teaching method raises the mean score we set H₀: x̄ = 70, Ha: x̄ > 70. We sampled 30 students, got x̄ = 74.2 and s = 8.5, and computed t = 2.71, p = 0.0056. So at α = .05 we reject H₀, meaning the new method has a 99.44% probability of being effective. The 95% CI is 74.2 ± 1.96 × 8.5 = [57.54, 90.86]. If we sample another 30 students tomorrow and it is significant again, that proves the effect even more."
顯示詳解 / Show solution
  1. 錯 1：假設寫到樣本統計量 / Error 1: hypotheses about a sample statistic
    H₀: x̄ = 70 是錯的。假設永遠是對母體參數 μ 的陳述；x̄ 是已經算出來的數字，要嘛等於 74.2 要嘛不等於，沒有檢定的必要。改為 H₀: μ = 70 vs Ha: μ > 70。
    H₀: x̄ = 70 is wrong. Hypotheses are always statements about the population parameter μ. x̄ is a known number (74.2)—there is nothing to test. Use H₀: μ = 70 vs Ha: μ > 70.
  2. 錯 2：把 p 值講成「有效的機率」/ Error 2: p-value as probability the effect is real
    「99.44% 機率有效」是典型的 p 值誤解。p = 0.0056 的意思是：假設 H₀ 為真時，看到這麼極端（或更極端）資料的機率是 0.56%。它不是 Ha 為真的機率，也不是「結果有 99.44% 可重現」。正確說法是「資料提供強烈證據反對 H₀」。
    "99.44% probability of being effective" is the classic p-value fallacy. p = 0.0056 means: if H₀ were true, the chance of data this extreme or more is 0.56%. It is not the probability that Ha is true, nor a 99.44% replication probability. Say "the data provide strong evidence against H₀".
  3. 錯 3：CI 用錯臨界值、忘了除以 √n / Error 3: wrong CI critical value, missing √n
    σ 未知 → 應配 t₀.₀₂₅,₂₉ = 2.0452，且標準誤是 s/√n = 8.5/√30 = 1.5519：
    CI = 74.2 ± 2.0452 × 1.5519 = 74.2 ± 3.174 = [71.03, 77.37]。
    助理的 1.96 × 8.5 = 16.66 把 s 當成 SE 還用了 Z 臨界值，區間被脹大 5 倍，15 到 90 的範圍幾乎什麼都包進去了。
    σ unknown → use t₀.₀₂₅,₂₉ = 2.0452 with SE = s/√n = 8.5/√30 = 1.5519:
    CI = 74.2 ± 2.0452 × 1.5519 = 74.2 ± 3.174 = [71.03, 77.37].
    The assistant used s as if it were the SE and applied 1.96, inflating the interval about fivefold—a range from 15 to 90 covers almost everything.
  4. 錯 4：一直抽到顯著為止 / Error 4: sampling until significant
    這就是 Q19 提過的 peeking / 重複檢定。每次重算都有 5% 誤報機會，且「顯著就停」會挑到隨機波動最高的樣本，讓效果被高估。必須事先定樣本數與停止規則；或改用序貫設計。
    This is the peeking problem from Q19. Each recomputation carries a 5% false-alarm chance, and stopping at significance selects the randomly inflated sample. Pre-specify sample size and stopping rule, or use a sequential design.
  5. 錯 5（加分）：沒有效果量 / Bonus error 5: no effect size
    報告只講「顯著」，沒講差多少。這裡估計效果是 74.2 − 70 = 4.2 分，95% CI [71.03, 77.37] 換算成效果量是 [1.03, 7.37] 分。有沒有教學實務上的意義，要教的判斷，不是 p 值能給的。另外 α 也沒說明是事前定的。
    The report says "significant" but never says how much. The estimated effect is 74.2 − 70 = 4.2 points, with CI [71.03, 77.37] translating to an effect of [1.03, 7.37] points. Practical significance is a teaching judgment, not something a p-value supplies. α was also never declared as pre-specified.
  6. t = 2.71 和 p = 0.0056 本身對不對 / Are t and p correct?
    對。t = 4.2/(8.5/√30) = 2.706；p = P(t₂₉ > 2.706) = 0.00564。這題的陷阱正是：計算完全正確，錯的是解讀。很多人只檢查數字，所以抓不到這種報告的問題。
    Yes. t = 4.2/(8.5/√30) = 2.706; p = P(t₂₉ > 2.706) = 0.00564. The trap here is that the arithmetic is perfectly correct—only the interpretation is wrong. People who check numbers alone will miss it.
答案：① 假設要寫 μ 不是 x̄；② p 值不是「有效的機率」；③ CI 應用 t = 2.0452 且 s/√n，正解 [71.03, 77.37]；④ 重複偷看會膨脹 α；⑤ 沒報告效果量。t 與 p 的計算本身是對的。Answer: ① Hypotheses use μ, not x̄; ② p is not the probability the effect is real; ③ the CI needs t = 2.0452 and s/√n, giving [71.03, 77.37]; ④ repeated peeking inflates α; ⑤ no effect size reported. The t and p arithmetic itself is correct.
